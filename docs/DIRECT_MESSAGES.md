# 1:1 DM 채팅

## 구현 범위

- PC: 대화 목록과 선택한 대화를 함께 표시. 모바일: 목록/대화 화면 전환.
- 닉네임으로 새 대화 시작, 같은 두 사용자의 기존 방 재사용, 대화 상대 검색.
- 텍스트 말풍선, 한국 시간/날짜 구분, Enter 전송 및 Shift+Enter 줄바꿈. 한글 조합 중 Enter는 전송하지 않음.
- SSE를 통한 자동 수신, 목록 미리보기/정렬, 방별 미확인 개수 및 합계.
- 활성 탭에서 최신 메시지까지 보고 있을 때 읽음 처리. 과거 대화를 읽는 동안에는 스크롤 유지 및 새 메시지 버튼 표시.
- 최신 50개부터 시작, 위로 스크롤하거나 버튼을 누르면 이전 50개를 추가하고 스크롤 위치 유지.
- 전송 중/실패/재전송, UUID 기반 중복 저장 방지. 사용자·방별 초안과 미확정 전송은 탭의 sessionStorage에 보관.
- 재연결 시 마지막으로 동기화한 메시지 이후를 100개씩 복구. 자신의 전송 응답은 동기화 커서를 앞당기지 않음.

사진/첨부, 입력 중 표시, 접속 상태, 반응, 전송 취소, 푸시 알림은 이번 텍스트 채팅 범위에 포함되지 않는다.

## 실행

```powershell
npm.cmd ci
npm.cmd run dev
```

기존 `.env.local`의 `MONGODB_URI`, `AUTH_SECRET`을 사용한다. MongoDB는 트랜잭션을 지원하는 Atlas 또는 replica set이어야 한다. 별도 실시간 서비스 키나 WebSocket 서버는 필요하지 않다.

## 자동 갱신 방식과 운영 특성

브라우저는 `/api/messages/stream`에 EventSource 연결을 유지한다. 서버가 약 2초 간격으로 DB를 조회하고 바뀐 대화 목록과 최신 메시지 스냅샷만 SSE로 전달한다. 즉 수신 지연은 보통 약 2초에 DB/네트워크 시간이 더해지며, DB change stream 또는 WebSocket 기반 즉시 push 방식은 아니다.

연결은 약 24초 후 종료되고 EventSource가 재연결하며 새 요청에서 인증을 다시 확인한다. 탭이 숨겨지거나 오프라인이면 연결을 닫고, 복귀하면 연결 및 누락 내역을 복구한다. 응답에는 private/no-store/no-transform과 X-Accel-Buffering: no를 설정한다. 배포 프록시가 SSE를 버퍼링하지 않는지 확인해야 한다.

열린 화면마다 약 2초 간격으로 조회하므로 동시 사용자가 많아지면 DB 부하/함수 실행 비용을 측정해야 한다. 향후 규모가 커질 때는 관리형 pub/sub 또는 별도 연결 서버로 수신 계층을 교체할 수 있다. 현재 수신은 쪽지 화면이 열려 있을 때 제공하며 앱 전체 알림은 제공하지 않는다.

## API·권한·저장

- GET `/api/messages`: 내 방 목록. `roomId`로 최신 대화, `before`로 과거 페이지, `after`로 누락 메시지(최대 100개와 hasMore)를 조회.
- POST `/api/messages`: `{ roomId, content, clientMessageId }`. UUID가 같은 재전송은 기존 메시지를 반환하며 다른 본문이면 409.
- POST `/api/messages/read`: `{ roomId, through }`. 실제 해당 방 메시지까지 읽음 처리.
- GET `/api/messages/stream?roomId=...`: 목록 및 선택한 방의 snapshot 이벤트. roomId를 생략하면 목록만 전달.
- 모든 API에서 세션 확인. 조회/전송/읽음은 세션 사용자의 대화방 참여 조건으로 제한. 발신자는 세션, 수신자는 DB 대화방에서 결정.
- 요청은 Zod로 파싱. POST는 동일 Origin 및 JSON 형식 확인, 본문 16KiB 제한. 텍스트는 JSX로 렌더링.
- 메시지와 방 미리보기는 하나의 트랜잭션으로 저장. 읽음 플래그와 방의 사용자별 readThrough도 하나의 트랜잭션으로 갱신. readThrough는 $max로 역행 방지.
- Message의 `(room, sender, clientMessageId)` 부분 고유 인덱스로 동시 재전송 중복 방지. 기존 UUID 없는 메시지는 유지. 추가 조회 인덱스도 모델 초기화 시 생성하므로 DB 계정에 인덱스 생성 권한 필요.
- 기존 participantKey와 쪽지 데이터는 그대로 재사용. 기존 Server Action 전송은 구형 화면 호환을 위해 유지하되 새 채팅 화면은 새 API 사용.

## 검증

```powershell
npm.cmd run test:messages
npm.cmd run lint
npm.cmd run build
npm.cmd run test:messages:integration
```

단위 테스트는 실제 서버 모듈을 인증/DB 어댑터와 함께 실행해 권한, 입력, 중복 전송, 읽음 범위, CSRF 및 메시지 병합을 확인한다.

통합 테스트는 `mongodb-memory-server`로 localhost 전용 임시 replica set과 별도 Next.js 서버(기본 3101)를 띄운다. 외부 DB와 기존 계정은 사용하지 않는다. 첫 실행 시 MongoDB 바이너리를 다운로드하며 테스트 후 임시 DB와 서버를 종료한다. 인증, 비참여자 접근 차단, 동시 중복 전송, 열린 SSE 연결로 새 메시지 수신, 미확인 개수, 읽음 역행 방지, 과거 내역 및 100개 이상 누락 복구를 확인한다. 먼저 build를 실행해야 한다.

`node tests/chat-local.cjs --ui`는 테스트 후 로컬 서버를 유지한다. 임시 로그인 정보는 Git에서 제외된 `.next/chat-fixture.json`에 있으며 Ctrl+C로 서버와 DB를 정리한다. 외부 DB에 대한 통합 테스트는 명시적 승인 없이 실행하지 않는다.

### 브라우저 수동 확인

1. 일반 창/시크릿 창에서 A/B로 로그인. 같은 대화방에서 양방향 전송 시 새로고침 없이 수신되는지 확인.
2. 다른 방 또는 쪽지 목록에서 미확인 배지가 증가하고, 해당 방의 맨 아래로 이동하면 읽음/배지가 갱신되는지 확인.
3. 과거 대화로 스크롤한 뒤 상대가 전송하면 위치가 유지되고 새 메시지 버튼으로 최신 대화로 이동하는지 확인.
4. 네트워크를 끊고 전송해 실패/재전송을 확인. 다시 연결한 후 같은 메시지가 하나만 저장되는지 확인.
5. 탭을 숨겼다가 복귀해 누락 메시지와 목록이 복구되는지 확인.
6. 초안 작성 후 다른 방 이동/복귀, 실패 메시지가 있는 상태에서 새로고침 후 재전송을 확인.
7. 한글 조합 Enter, Shift+Enter 줄바꿈, 긴 본문, 모바일 키보드와 화면 전환 확인.
8. C로 A/B 방의 페이지·API·SSE·읽음 요청을 호출해 내용 조회나 변경이 불가능한지 확인.
